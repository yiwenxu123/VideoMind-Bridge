## 8. v1 Legacy 深入分析

### 8.1 它到底是什么

v1 = 「下载 → 转录 → AI 摘要 → 导出」的完整流水线，共三层：

| 层 | 组成 | 行数 | 入口 |
|---|---|---|---|
| 服务层 | `download_service`、`transcribe_service`、`ai_service`、`export_orchestrator`、`task_database`、`duplicate_detector`、`time_estimator`、`prompt_template`、`downloaders/*` | ≈3600 | CLI `--mode full/download/transcribe`、API `/api/v1/tasks*` |
| 外壳层 | `src/gui/**`、`browser-extension/**`、`web/index.html` + `web/settings.html`（`/legacy`）、`WS /ws` | GUI 5319 + 扩展 10 文件 | GUI、扩展 |
| 复用层 | `src/exporters/**`、`src/models/task.py` | 1409 + 184 | **v2 归档也用它** |

### 8.2 关键：v1 不是一座孤岛

`src/core/archiver.py`（v2 的「提取即归档」）直接 import：

```
src/core/archiver.py:16  from ..exporters.html_player_exporter import HTMLPlayerExporter
src/core/archiver.py:24  from ..services.export_orchestrator import ExportOrchestrator
```

而 `/api/v1/extract/archive` 与 CLI `--archive` 都走 archiver（`src/api/server.py:576`、`src/cli.py:482`）。
换言之：**删掉 v1 导出层，v2 的归档功能一起废**。
另外 API 每次启动都会实例化 v1 的 `TaskManager`（`src/api/server.py:285`、`:318`），它启动时会加载 AI 服务（启动日志 `AI服务已启用，模型: deepseek-chat`），并提供 `/api/v1/status` 与 `/tasks*`。

### 8.3 依赖矩阵（谁还在用 v1）

| v1 模块 | 唯一使用者 | 能否直接删 |
|---|---|---|
| `download_service`、`transcribe_service`、`ai_service` | `task_manager`、`cli`（v1 模式） | 随外壳一起删才安全 |
| `task_manager`、`task_database` | `api/server.py`（`/status`、`/tasks`、启动时初始化） | 需先改 `/status` 与 lifespan |

| `config_manager` | 几乎所有模块（含 ASR） | 必须保留 |
| `duplicate_detector`、`time_estimator`、`prompt_template` | v1 流水线 / GUI | 可随外壳删 |
| `models/task.py` | `archiver`、`cli`、`exporters` | **不能直接删**（`ExportContext` 等被 v2 归档复用） |

### 8.4 三种移除方案

| 方案 | 做什么 | 收益 | 风险 | 工期[推断] |
|---|---|---|---|---|
| **A. 只删外壳**（推荐先做） | 删 `src/gui/**`、`browser-extension/**`、`web/index.html`+`web/settings.html`、`/legacy`、`/ws`、`/api/v1/tasks*`、CLI 的 `--mode/--model/--targets/--keep-video/--video-quality/--cookie-browser`、`task_manager`+`task_database` | 少 ≈11000 行与 1 个 WS 通道；安装体积与依赖下降 | 中：`/status` 要改为读进程内统计；启动不再初始化 TaskManager | 2-3 天 |
