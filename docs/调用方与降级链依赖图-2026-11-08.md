# VideoMind Bridge 调用方与降级链依赖图

> **生成**：2026-11-08（基于当日全仓 grep 实证；由内容运营agent 接入行动计划的分析产出）
> **用途**：排查「视频提取为什么失败」时先看这张图——确认调用方是谁、VMB 挂了会降到哪
> **定位声明**：VMB = 视频**提取**中枢（URL → 成本预筛 → 文字提取 → 入库），非视频文件下载工具（下载属 v1 Legacy，已冻结）

## 一、调用关系全景

```
                    ┌─ Hermes video-content-extractor ─┬─ ① MCP videomind（Mac :8787）←首选
  视频提取需求 ──────┤  （Hermes skill，tier: core）     ├─ ② REST 公网（腾讯云 124.222.71.123/vmb）
                    │                                  └─ ③ 平台字幕API → ④ yt-dlp+SenseVoice/whisper
                    │                                     → ⑤ 云ASR → ⑥ 商业API（自身4级降级链，VMB挂了也能活）
                    │
                    ├─ 内容运营agent ContentExtractor ──┬─ VMB（VMB_PLATFORMS = bilibili/抖音/小红书）
                    │  （对标拆解链）                    └─ 本地 Defuddle/JSDOM 回退（VIDEO_EXTRACT_BACKEND）
                    │   VideoMindClient.js: guards + strict 开关 + fallback 统计
                    │
                    └─ 内容运营agent BenchmarkService ─── VMB comments（作品评论兜底：评论为空且传 postId 时）

  不依赖 VMB 的相邻能力（防误判）：
  · content-theme-finder（Hermes）   纯信号采集（intel-pipeline/RSSHub/Tavily），完全不碰视频
  · 视频生产管线 services/video/    走 media-engine 引擎仓（与 VMB 职责无关）
  · agent-reach（2026-11 新接入）    B站搜索/对标/字幕备选——独立通道，不做下载不做转写
  · ego lite 直读（2026-11 新接入）  小红书正文/评论（用户已登录会话，agent 会话内按需调用）
  · HanaAgent                       清单里登记了 videomind MCP，但以 uv run --directory 方式调，非常驻依赖
```

## 三、降级链速查（谁挂了降到哪）

| 故障场景 | 降级行为 |
|---|---|
| Mac VMB（:8787）挂 | video-content-extractor → 公网 REST → 自有 yt-dlp+whisper；ContentExtractor → local Defuddle（注意：B站 local 提取可能产出页面 UI 碎片，内容质量需检查，见 benchmark-decompose-assist skill） |
| 公网 REST 401/5xx | video-content-extractor 的调用约定即放弃该级，继续往下走 |
| VMB 内某平台提取器失效 | v2 Engine 9 提取器自动降级（B站/YouTube/抖音/小红书/yt-dlp/tikhub/Apify/阿里云ASR），免费优先于付费 |
| ASR 服务不可用 | 本地 SenseVoice → faster-whisper（零 Key） |

## 五、边界与禁区

- v1 Legacy（视频文件下载 + 浏览器扩展）已冻结：真有下载需求直接用 yt-dlp，**不复活 v1**
- 新调用方接入优先走 MCP（prescreen_video / smart_extract / extract_video / archive_extract），不直连内部模块
- 采集合规：自动化巡检只用 RSS（不自动请求平台），见内容运营agent 10-10 采集合规定稿
